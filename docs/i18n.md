# 界面文案与动态语言切换（i18n）

> 状态：**已实现**。翻译文件随包发布在 `resources/i18n/`，默认界面语言是
> **简体中文**；语言配置在 `[ui] language`，设置页（`Appearance → Language`）
> 里可即时切换中英，无需重启。

## 为什么不是「一次性把所有字符串拿去翻译」

Qt 的 `self.tr()` 只在**取文案的那一刻**查一次翻译表。动态切换语言的难点
不是把字符串包进 `tr()`，而是「切换之后，界面上已经显示的文字怎么换成新语言」：

1. `QApplication` 装载 / 卸载 `QTranslator` 时，Qt 只把
   `QEvent.LanguageChange` 发给**顶层窗口**，嵌套控件收不到；
2. presenter / model / delegate 不是控件，根本收不到事件；
3. 用作文案**标识**的字符串（例如搜索栏模式名）如果直接拿展示文本比较，
   切换语言后逻辑就断了。

所以这套设施解决三件事：翻译器装卸、控件文案重放、非控件对象重建文案。

## 组成部分

| 位置 | 职责 |
| --- | --- |
| `albuswall.ui.languages` | 语言注册表（纯数据，不 import Qt）：`LANGUAGES` / `language_choices()` / `language_label()` / `DEFAULT_LANGUAGE` |
| `albuswall.ui.builtin.i18n.manager` | `TranslationManager`（装 / 卸 `QTranslator`、广播 `language_changed`、遍历控件重放文案）、模块级 `tr(context, text)`、单例 `translation_manager()` |
| `albuswall.ui.builtin.i18n.retranslate` | `Retranslatable` 混入：`QEvent.LanguageChange` → `retranslate_ui()` |
| `resources/i18n/` | `albuswall_<lang>.ts`（可编辑源）+ `albuswall_<lang>.qm`（运行期） |
| `scripts/build_i18n.py` | 构建 `.ts` / `.qm`；词表在 `scripts/i18n_catalog.py` |

### 翻译文件

```
src/albuswall/resources/i18n/
├── albuswall_en_US.ts     # Qt Linguist 可编辑
├── albuswall_en_US.qm     # 运行期加载
├── albuswall_zh_CN.ts
└── albuswall_zh_CN.qm
```

仓库里的界面源文是**中英混排**的，所以两个语种各补自己缺的部分：

* `zh_CN` 只写**英文**源文的中文译文；
* `en_US` 只写**中文**源文的英文译文；
* 源文本身就是目标语言时不写条目，Qt 自动回退到源文。

重新构建（改了文案 / 词表之后）：

```bash
python scripts/build_i18n.py            # 提取 + 补缺失译文 + 生成 .qm
python scripts/build_i18n.py --refresh  # 用词表覆盖 .ts 里的旧译文
python scripts/build_i18n.py --check    # 只检查是否还有缺译文（退出码非 0）
```

`.ts` 里已有的译文不会被默认覆盖，所以在 Qt Linguist 里手工改过的内容能保留；
新增文案由 `pyside6-lupdate` 自动出现在 `--check` 的缺失列表里。

lupdate 只能提取 `self.tr(...)`；模块级 `tr()` 和 `schema_tr()` 的上下文由
`scripts/i18n_catalog.py::MANUAL_CONTEXTS` / `schema_strings()` 补齐
（后者在构建时从设置树登记表里实体化，不会漂移）。

## 配置

语言是 **UI 引导配置**，和主题同属 `[ui]` 节：

```ini
[ui]
# 可选 zh_CN（默认）/ en_US；见 albuswall/ui/languages.py
language = zh_CN
```

代码里统一走 typed dict：

```python
from albuswall.ui.bootstrap import ui_config

ui_config()["language"]     # -> "zh_CN"
```

启动时 `Application.setup()` 会调 `translation_manager().install()`：按
`[ui] language` 装翻译器（`resources/i18n/albuswall_<code>.qm`，外加
PySide6 自带的 `qtbase_<code>.qm`），找不到就静默跳过并载入原文。

设置页的位置：**`Appearance → Language`**（外观分组里，「主题」与「窗口标题」
之间；配置节点 `[ui] language`，`services/command.py` 的
`appearance.language` 叶子）。写回成功后：

1. `setting.set`（CLI）或设置页的 `SettingController.applied`（GUI）触发
   `translation_manager().install(value)`；
2. 装新翻译器；
3. 遍历 `QApplication.allWidgets()`，对每个实现了 `retranslate_ui()` 的控件重放；
4. 广播 `language_changed`，让 presenter / model 重算文案。

## 写界面文案的约定

### 1）控件：能拿到 `self` 就用 `self.tr`

```python
class Foo(Retranslatable, QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._setup_ui()       # 只建控件，不写文案
        self.retranslate_ui()  # 首次应用文案

    def _setup_ui(self):
        self.label = QLabel(self)   # 不传文案

    def retranslate_ui(self):
        self.label.setText(self.tr("Hello"))
```

* 文案统一放在 `retranslate_ui()`，并且在构造函数里调一次；
* `retranslate_ui()` 必须**幂等**、只改文案（不重建控件、不丢用户输入）；
* 混入必须放在 Qt 基类**之前**：`class Foo(Retranslatable, QWidget)`。

### 2）没有 `QObject` 上下文：用模块级 `tr`

model / delegate / 纯函数：

```python
from ..i18n import tr

_TR_CONTEXT = "MetadataModel"

def _label(text: str) -> str:
    return tr(_TR_CONTEXT, text)
```

上下文取所在类名，保持稳定。这类调用 lupdate 看不到，源文要登记在
`scripts/i18n_catalog.py` 的 `MANUAL_CONTEXTS` 里。paint 期间取译文的
delegate（例如删除倒计时）需要在语言切换后重绘 —— 由对应 presenter 的
`retranslate()` 触发 `view.update()`。

### 3）presenter：实现 `retranslate()`

presenter 不是控件，需要自己重建文案：

```python
def retranslate(self) -> None:
    self.reload()          # 例如重刷卡片标题的「未命名」兜底
```

`PresenterManager` 会在 `build()` 时统一订阅 `language_changed`，在
`teardown()` 时解绑，并逐个调用 `presenter.retranslate()`，所以 presenter
只要**定义** `retranslate()` 即可。

### 4）文案标识 ≠ 展示文本

任何被用来做逻辑判断的字符串，都必须是稳定标识：

```python
MODE_SIMPLE = "simple"     # 标识（itemData / 判断用）
MODE_COMMAND = "command"

def _mode_text(self, mode: str) -> str:   # 展示文本（itemText / tr）
    return self.tr("命令模式") if mode == self.MODE_COMMAND else self.tr("简单模式")
```

参考实现：`widgets/floating_search_bar.py`。

### 5）设置页：配置结构带下来的文案

`setting.schema` 里的分组标题 / 叶子标签 / 说明来自配置数据，不是某个控件
写的句子，统一走**固定上下文**翻译：

```python
from .translation import schema_tr

label.setText(schema_tr(item["label"]))
```

这些字符串由 `scripts/i18n_catalog.py::schema_strings()` 在构建时从登记表里
实体化，不需要手工维护。写回配置的永远是原始文本，不要用译文覆盖 schema dict。

## 新增语言

1. 在 `albuswall/ui/languages.py` 的 `LANGUAGES` 里加一行
   （`Language("ja_JP", "日本語")`）——设置页下拉框会自动出现；
2. 在 `scripts/i18n_catalog.py` 的 `TRANSLATIONS` 里加一个词表
   （`LANGUAGES` 自动从 UI 语言注册表取到新语种）；
3. 跑 `python scripts/build_i18n.py` 生成 `.qm`；
4. 用 `--check` 确认没有遗漏（源文与目标语言相同时不需要条目）。

## 已知边界

* **服务层错误消息**（`TagError` 等）目前是中文常量，将来会通过 toast 显示；
  要翻译它们需要把异常消息改成可翻译的错误码，属于独立改造。
* **插件自带的文案**（`settings/extras.py` 注册的）走 `SettingSchema`
  上下文，插件作者可以在自己的 `.ts` 里补，或者复用 `schema_tr`。
* **命令行 `albusctl`** 的输出属于面向脚本的接口，暂不翻译。
